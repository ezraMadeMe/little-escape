# Dev Console - God Mode Simulation UI Guide

## 개요

Dev Console은 백엔드의 God Mode Simulation API를 제어하기 위한 어드민 대시보드입니다.

개발자가 **클릭 몇 번**으로 "한여름 장마철 월요일 밤의 I성향 유저" 같은 복잡한 시나리오를 재현할 수 있습니다.

---

## 접속 방법

```
http://localhost:5173/dev-console
```

**주의**: 이 페이지는 **인증 없이** 접근 가능합니다. (개발 편의성)

---

## UI 구조

### 왼쪽 패널: 입력 컨트롤 (4개 섹션)

#### 1️⃣ 시공간 설정 (Time & Space)

- **날짜 & 시간**: `datetime-local` 입력
- **위치 프리셋**: 성수동, 강남역, 홍대, 여의도, 서울역 버튼
- **위도/경도**: 직접 입력 가능 (소수점 4자리)
- **반경 슬라이더**: 1km ~ 20km

#### 2️⃣ 환경 변수 (Environment)

- **날씨**: 아이콘 선택
  - ☀️ 맑음 (SUNNY)
  - 🌧️ 비 (RAIN)
  - ❄️ 눈 (SNOW)
  - ☁️ 흐림 (CLOUDY)
- **기온**: -20°C ~ 40°C 슬라이더
- **미세먼지**: 좋음 / 나쁨 / 최악
- **혼잡도**: 한적함 / 보통 / 터짐

#### 3️⃣ 사용자 페르소나 (User)

- **MBTI**: I (내향형) / E (외향형) 토글
- **솔로 레벨**: 1~5 별점 ⭐
- **카테고리 강제 지정**: 선택 사항
  - 🍽️ 음식 (FOOD)
  - 🏃 활동 (ACTIVITY)
  - ☕ 휴식 (RELAX)
  - 🎭 문화 (CULTURE)

#### 4️⃣ 액션 버튼

- **🎲 랜덤 시나리오**: 모든 값을 무작위로 채움
- **▶️ 시뮬레이션 실행**: API 호출 및 결과 표시

---

### 오른쪽 패널: 결과 (Result & Logs)

#### ✅ 추천된 미션

- 미션 제목, 설명
- 카테고리, 난이도, 장소 타입, 시간대 태그

#### 📍 추천된 장소

- 장소 이름, 주소
- 카테고리, 태그

#### 📊 통계

- 전체 미션 후보 / 필터링 후 미션
- 전체 장소 후보 / 필터링 후 장소

#### 🖥️ Debug Logs (터미널 스타일)

백엔드에서 반환된 디버그 로그를 **실시간으로 표시**합니다.

```
[1] 🕒 시뮬레이션 시간: 2025-01-20T14:30:00 (MONDAY, 14시)
[2] 📍 위치: (37.5665, 126.9780), 반경: 10km
[3] ☁️ 날씨: RAIN, 기온: 12.0°C, 미세먼지: GOOD
[4] 👥 혼잡도: MEDIUM, MBTI: E, 솔로레벨: 4
[5] ⏰ 시간대: 오후 (AFTERNOON)
[6] 🌧️ 야외 활동 제한 - 실내 장소만 추천
[7] 📋 조건에 맞는 미션 후보: 8개
[8] 📅 월요일 - 도서관 미션 제외 (1개 제외됨)
[9] ✅ 필터링 후 미션 후보: 7개
[10] ✅ 선택된 미션: 혼자만의 시간, 카페에서 책 읽기
[11] 🏠 장소가 필요한 미션 - 장소 필터링 시작
[12] 🗂️ 매칭 카테고리: [RELAX, CULTURE]
[13] 📍 반경 10km 내 필터링된 장소: 32개
[14] ✅ 선택된 장소: 북촌 한옥마을 카페
```

**색상 코딩**:
- 🟢 초록 (✅): 성공/선택
- 🔴 빨강 (❌): 제외/실패
- 🟡 노랑 (⚠️): 경고

## 사용 예시

### 시나리오 1: 월요일 도서관 필터링 검증

1. **날짜 & 시간**: 2025-01-20 (월요일) 14:00
2. **위치**: 성수동 프리셋 선택
3. **날씨**: ☀️ 맑음
4. **기온**: 20°C
5. **미세먼지**: 좋음
6. **혼잡도**: 한적함
7. **MBTI**: I
8. **솔로 레벨**: 3
9. **시뮬레이션 실행** 클릭

**기대 결과**:
- Debug Logs에서 "📅 월요일 - 도서관 미션 제외" 확인
- 도서관 관련 미션이 추천에서 제외됨

---

### 시나리오 2: 비오는 날 실내 추천 검증

1. **랜덤 시나리오** 클릭 (기본값 채우기)
2. **날씨**: 🌧️ 비 선택
3. **기온**: 12°C
4. **미세먼지**: 좋음
5. **시뮬레이션 실행** 클릭

**기대 결과**:
- Debug Logs에서 "🌧️ 야외 활동 제한 - 실내 장소만 추천" 확인
- 추천된 미션의 장소 타입이 `INDOOR` 또는 `ANY`

---

### 시나리오 3: 극한 환경 테스트 (랜덤)

1. **🎲 랜덤 시나리오** 클릭
2. 자동으로 모든 값이 무작위로 채워짐:
   - 랜덤 날짜/시간 (다음 7일 내)
   - 랜덤 위치 (5개 프리셋 중 하나)
   - 랜덤 날씨/기온/미세먼지/혼잡도
   - 랜덤 MBTI/솔로레벨
3. **시뮬레이션 실행** 클릭

**용도**: 빠른 반복 테스트, 예외 상황 발견

## 주요 기능

### 🎲 랜덤 시나리오 생성

클릭 한 번으로 다음 값들이 자동 설정됩니다:

- **날짜/시간**: 현재 ~ 7일 후 랜덤
- **위치**: 5개 프리셋 중 랜덤
- **반경**: 5~15km 랜덤
- **날씨**: SUNNY/RAIN/SNOW/CLOUDY 랜덤
- **기온**: -10~35°C 랜덤
- **미세먼지**: GOOD/BAD/WORST 랜덤
- **혼잡도**: LOW/MEDIUM/HIGH 랜덤
- **MBTI**: I/E 랜덤
- **솔로 레벨**: 1~5 랜덤
- **카테고리**: 자동/FOOD/ACTIVITY/RELAX/CULTURE 랜덤

**사용 팁**:
- 버그 헌팅할 때 랜덤 시나리오를 10번 정도 돌려보면 예외 상황을 빠르게 발견할 수 있습니다.

### 🖥️ Debug Logs 읽는 법

각 로그 라인은 추천 과정의 특정 단계를 나타냅니다:

```

[3] ☁️ 날씨: RAIN, 기온: 12.0°C, 미세먼지: GOOD
    → 입력된 환경 변수

[4] 👥 혼잡도: MEDIUM, MBTI: E, 솔로레벨: 4
    → 입력된 사용자 정보

[5] ⏰ 시간대: 오후 (AFTERNOON)
    → 시간대 분석 결과

[6] 🌧️ 야외 활동 제한 - 실내 장소만 추천
    → 날씨 기반 필터링

[7] 📋 조건에 맞는 미션 후보: 8개
    → 초기 미션 후보 개수

[8] 📅 월요일 - 도서관 미션 제외 (1개 제외됨)
    → 시간 기반 필터링 (핵심!)

[9] ✅ 필터링 후 미션 후보: 7개

    → 랜덤으로 선택된 미션

    → 장소 검색 시작

    → 미션 카테고리에 매칭되는 장소 카테고리

[13] 📍 반경 10km 내 필터링된 장소: 32개
    → 거리/키워드 필터링 후 장소 개수

[14] ✅ 선택된 장소: 북촌 한옥마을 카페
    → 랜덤으로 선택된 장소
```

## 개발 워크플로우

### 1. 새로운 필터 로직 추가 시

1. 백엔드에서 `SimulationService` 수정
2. Dev Console에서 해당 조건 설정
3. Debug Logs로 필터링 확인
4. 기대한 대로 동작하는지 검증

### 2. 버그 리포트 검증 시

사용자가 "월요일에 도서관이 추천됨"이라고 리포트한 경우:

1. Dev Console 접속
2. **날짜**: 월요일로 설정
3. **카테고리**: CULTURE 강제 지정
4. **시뮬레이션 실행**
5. Debug Logs에서 "월요일 - 도서관 미션 제외" 로그 확인
6. 로그가 없다면 버그 확정 → 백엔드 수정

### 3. 성능 테스트 시

1. **랜덤 시나리오** 클릭
2. **시뮬레이션 실행**
3. 응답 시간 측정 (Network 탭)
4. Debug Logs에서 후보 개수 확인
   - `totalMissionCandidates`: 100개 이하 권장
   - `filteredMissionCandidates`: 10~30개 적정

## API 연동

Dev Console은 다음 API를 호출합니다:

```
POST http://localhost:8080/api/admin/simulation
```

**Request Body**:
```json
{
  "targetDateTime": "2025-01-20T14:00:00",
  "latitude": 37.5665,
  "longitude": 126.9780,
  "searchRadius": 10,
  "weather": "SUNNY",
  "temperature": 20.0,
  "airQuality": "GOOD",
  "congestion": "LOW",
  "userMbti": "I",
  "soloLevel": 3,
  "forcedCategory": "FOOD"
}
```

**Response**:
```json
{
  "mission": { ... },
  "place": { ... },
  "debugLogs": [ ... ],
  "totalMissionCandidates": 12,
  "filteredMissionCandidates": 10,
  "totalPlaceCandidates": 45,
  "filteredPlaceCandidates": 45
}
```

## 문제 해결

### 시뮬레이션 실행 시 오류

**오류**: `Network Error` 또는 `Connection Refused`

**원인**: 백엔드 서버가 실행되지 않음

**해결**:
```bash
cd backend
./gradlew bootRun
```

---

### 추천 결과가 없음

**오류**: `mission: null`, `place: null`

**원인**: 필터링 조건이 너무 엄격함

**해결**:
1. `searchRadius`를 20km로 늘리기
2. `forcedCategory`를 비우기 (자동 선택)
3. `soloLevel`을 5로 높이기

---

### Debug Logs가 너무 적음

**원인**: 백엔드에서 로그를 추가하지 않았을 수 있음

**확인**:
- `backend/src/main/java/com/littleescape/api/service/SimulationService.java` 확인
- `debugLogs.add(...)` 코드가 있는지 체크

## 향후 개선 계획

1. **시나리오 저장/불러오기**: 자주 사용하는 시나리오를 로컬 스토리지에 저장
2. **일괄 테스트 모드**: 여러 시나리오를 자동으로 순차 실행
3. **비교 모드**: 두 개의 시나리오 결과를 나란히 비교
4. **차트 시각화**: 필터링 전후 통계를 차트로 표시
5. **로그 다운로드**: Debug Logs를 텍스트 파일로 다운로드
